# 文件視覺一致性標準（輕量版）

在建立 DOCX、套用舊文件參照或修正表格位置時閱讀本規格。輕量版維持目前 plugin 的文件結構與既有字型；舊文件只提供可重用的視覺參照。由於本版沒有 DOCX renderer，幾何屬性以程式檢查，開啟後的字型替代、分頁與實際視覺結果只能在對話中標示為待使用者確認。

## 決策順序

1. 使用者對本文件的明確要求。
2. 本 plugin 的文件結構與必要內容。
3. 使用者提供的視覺參照或組織版型。
4. 本版預設版面基線。

參照文件可提供標題層級、配色、框線、間距、表頭、圖片及圖說關係；不能以其舊章節順序、更新紀錄位置、專案名稱或資料覆寫目前 plugin 規範。若未明示改版，沿用既有指定字型與文件結構。

修正前先分清「當前文件」與「參照文件」的實際狀態，逐項比對當前文件與適用規範。參照文件的不同不等於當前文件有缺陷；當前文件已符合規範且審核有效時，保持原狀，不為了修正參照文件的舊版差異而移動章節、重建或新增審核工作。

## 容器與表格幾何

對齊基準是元件所在的**容器可用內容區**：扣除頁面邊界、欄位、容器內距與適用頁首頁尾後，元件真正可使用的區域；它不等於整頁最大寬度。

- 每次由 `build_docx.py` 建表時，明確設定表格在容器內容區置中（`table.alignment = CENTER` 與直接 `w:jc w:val="center"`），並設為 `autofit`。
- 表格總寬、欄寬與列高依內容彈性調整，只要完整落在可用內容區；不要固定像素，也不要要求每張表填滿頁面。合法窄表仍應保留中心對齊，左右剩餘空間大致相等。
- 表格縮排、寬度類型與欄位網格要互相一致；不要因函式庫或內建模板的預設變動，讓原本置中的表格靠左。
- 只有使用者或明確版型要求靠左／靠右時，才使用其他對齊。沒有此要求時，若新模板造成靠左，需修正並重建文件。

圖片、圖說、提示框與正文沿用所在容器的對齊規則。文字不可讀時先分段、調整欄寬、縮放圖片或安排分頁，不任意縮小既定字型。表格、圖片或 build manifest 改動後，重新執行受影響的結構與獨立審核。

## 文件基線

- 預設 Letter 直式；左右 0.65 in、上 0.67 in、下 0.59 in。
- `fontName` 使用任務已指定的字型；`build_docx.py` 對正文與表格文字設定 East Asian 字型及 `zh-TW` 語言標記。不要因參照文件自行換成未確認字型。
- 標題區塊後緊接單一「更新紀錄」表；之後依序為修訂狀態、可選的版本依據、使用提醒、共通操作規則與功能章節。更新紀錄不可放在文末。
- 每個操作小節的步驟從 1 重新開始；紅框編號只對應同一張圖片內的控制項，圖說緊接圖片下方。

## 可驗證範圍

`verify_docx.py` 用於 DOCX 結構、章節順序、編號、欄位表、圖片封裝與圖說關係；`audit_delivery.py` 另檢查表格對齊／寬度屬性、媒體 hash 與 review evidence 綁定。程式通過不代表開啟後的字型、換行、圖片縮放或跨頁視覺已驗證。

輕量版不要求也不宣稱 DOCX renderer 結果。獨立 reviewer 仍須核對 layout_structure（可用的結構與幾何證據）；`render_visual` 固定記為 `not_performed` 或 `out_of_scope` 並附原因，不能填 `pass`。若使用者需要逐頁渲染，需另選具備 renderer 的工作流程；本版不安裝或呼叫 Documents、Word 或 LibreOffice。
