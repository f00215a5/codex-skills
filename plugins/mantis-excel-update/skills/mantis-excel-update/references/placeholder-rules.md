# 工作簿備註規則契約

此參考檔只定義處理契約；它不保存任何作用中的版本化規則、placeholder、來源活頁簿、工作表名稱、欄位名稱、公式、篩選值或統計設定。

## 規則的唯一來源

每次任務的規則來源只能是本次的「作用中工作簿副本」：

- 使用預設範本時，先複製 skill 的 assets/template.xlsx，再讀取副本內既有的儲存格備註。
- 使用者提供範本或既有更新檔時，先建立副本，再讀取該副本內既有的儲存格備註；不得併入預設範本的備註。
- 新的 ${...} 只有在使用者確認後，才可將對應規則寫入該輸出副本的儲存格備註。

版本化規則的標記與實際 payload 必須與儲存格一起留在作用中工作簿；skill 在執行時從備註辨識該標記，不在 skill 檔案另存名稱或內容。不得寫入、快取或同步到 SKILL.md、此參考檔、其他 skill 檔案或外部設定檔。若工作簿備註被修改，修改後的備註即為下一次更新的唯一真實來源。

## 可接受的規則形狀

有效規則應包含版本標記、單一 JSON 物件與可選的使用者可讀 placeholder。JSON 只能描述下列受限操作：

| operation | 用途 |
| --- | --- |
| count | 計算符合已確認條件的不重複問題單數 |
| list | 輸出符合已確認條件的問題單號清單 |
| text | 顯示可追溯的更新摘要 |
| formula | 寫入已確認的 Excel 統計公式 |
| snapshot | 在指定更新階段寫入固定值 |

規則若使用工作表、欄位、狀態分類、篩選條件、公式或計算時點，這些值都必須由該儲存格備註記錄，並與本次初始化確認一致。不要從此 skill 檔案補入預設值。

## 讀取、確認與寫入

1. 掃描作用中工作簿副本的儲存格值與備註，辨識既有有效規則及新的 ${...}。
2. 對新的 placeholder，將自然語言轉成候選的受限操作；若來源、篩選或結果格式不明確，先請使用者確認。
3. 寫入時保留原有人工備註，並在同一儲存格附加或更新有效規則區塊；不可覆寫人工文字。
4. 重跑時，以最新有效規則區塊為準。無效、歧義、包含外部路徑／跨活頁簿參照／程式碼／未確認自由文字篩選的規則不得執行，應回報使用者。
5. formula 只能引用作用中工作簿內已確認的工作表與範圍；snapshot 只能在已確認的更新階段取值。任何規則結果都要與問題單清單交叉核對。

## 交付邊界

內建 assets/template.xlsx 永遠是唯讀資產。每次只可修改工作副本並交付該輸出檔；不得把修改後的範本資產、備註規則或使用者工作簿內容回寫到 skill 目錄。
