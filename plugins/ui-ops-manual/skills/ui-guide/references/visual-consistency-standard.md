# 文件視覺一致性標準

在選擇參照文件、建立 DOCX 版面或修正表格／圖片位置時閱讀本規格。它固定視覺關係與版面幾何的判準，讓文件可依內容調整，同時避免產製器或模板更新造成漂移。

## 結構與風格分開決定

文件的章節順序、每章內容、操作步驟、欄位說明與驗證要求，遵循目前 `ui-guide` plugin 規範。使用者提供的既有文件只作視覺參照，除非使用者明示要沿用其文件結構；參照文件的專案名稱、畫面名稱與資料不得寫入共用模板或本規格。

視覺參照可提供標題層級、色彩、框線、間距、表格樣式、圖片與圖說的對齊方式。沒有明確參照時使用 [default-document-layout.md](default-document-layout.md)；CJK 字型選擇與渲染確認仍遵循 [cjk-render-preflight.md](cjk-render-preflight.md)，不因視覺參照自行更換未驗證字型。

優先順序如下：

1. 使用者對本文件的明確要求。
2. `ui-guide` plugin 的文件結構與必要內容。
3. 已選定的視覺參照或組織版型。
4. 本技能的預設版面基線，補足尚未指定的樣式。

若沒有使用者明示覆寫而規則之間衝突，保留 plugin 的結構要求，將參照文件的內容與系統特定資料排除，只採用可重用的視覺屬性；使用者已明示的本文件調整依確認結果執行。

## 可用內容區與置中

以所在頁面的**容器可用內容區**作為對齊基準：它是扣除頁面邊界、欄位、容器內距及適用頁首頁尾後，該元件真正可以使用的區域，不等於整頁的最大寬度。

- 表格預設在其容器可用內容區內置中。每次建置都明確設定表格對齊與容器／段落縮排，不依賴 Word、`python-docx` 或其他文件函式庫的目前預設值。
- 表格寬度、欄寬與列高依內容和版型彈性調整，只要完整落在容器可用內容區即可；不設定固定像素尺寸，也不要求每張表填滿區域。
- 同一類表格沿用相同的置中基準、表頭、框線、內距與文字對齊；不同內容可以有不同欄寬比例與總寬。
- 圖片、圖說、提示框及其他元件沿用其所在容器的對齊規則。局部放大圖可以縮小或拆分，但不可因產製器變動而無意間靠左、超出內容區或改變圖說相鄰關係。

若元件等於容器寬度，置中仍應保留為明確的版面設定；若元件較窄，左右剩餘空間應大致相等。只有使用者或版型明確指定靠左／靠右時才改用其他對齊。

## 共用視覺基線

固定下列可辨識的相對關係，尺寸則依內容與頁面換行調整：

| 元件 | 基線要求 |
| --- | --- |
| 標題與章標 | 沿用既有指定且已驗證的字型、既定層級與主色；以同一可用內容區為基準，各自沿用既定的置中或靠左樣式。 |
| 表格 | 表頭樣式、框線、內距與欄位標題一致；表格在容器內置中。 |
| 圖片與圖說 | 圖說緊接圖片下方，使用一致的對齊、間距與圖號／caption 規則。 |
| 提示與警示 | 沿用既定底色、邊框與文字層級；內容不加入執行環境或 renderer 警語。 |
| 步驟清單 | 每個操作小節從步驟 1 開始，清單與說明表使用同一正文區域。 |
| 分頁 | 長表重複表頭，避免標題孤行、圖片裁切、圖說單獨落頁與文字被截斷。 |

文字不可讀時先調整內容分段、欄寬、圖片比例或分頁；不要藉由任意縮小字型破壞既定層級。任何改變已選定視覺基線的個案調整，都在任務工作區建立可追溯副本並記錄偏離項目，不修改共用預設。

## 版面驗收

程式／結構檢查確認每個表格有明確對齊、寬度在容器內、欄位設定與樣式存在；它不能證明渲染後的視覺位置。使用最終 renderer 逐頁檢視，至少確認：

1. 表格相對於容器可用內容區置中，沒有受內建邏輯影響而靠左漂移。
2. 同類表格、圖片、圖說與提示框維持相同的視覺關係；寬度差異有內容或版型依據。
3. 頁面邊界、截圖比例、紅框可讀性、caption 相鄰性與跨頁行為正常。

渲染工具、CJK glyph 與審核環境的結果只在對話或外部 review artifact 回報，不寫入 DOCX；依 [render-and-annotation-qa.md](render-and-annotation-qa.md) 執行兩道 QA。

後續輪次可依 [incremental-qa-workflow.md](incremental-qa-workflow.md) 承接 baseline 中已通過或使用者明示接受、且 hash／依賴可驗證的未變資產語意結果，但版面驗收仍逐頁檢查整份最終文件；版型、builder、margin、字型或圖片尺寸規則等全域變更會使所有頁面受影響。hash 不能代替像素位置、裁切或可讀性的檢查。
